# 循环任务功能方案

## 概要

在现有任务上增加循环规则，并将“任务模板”与“每次完成记录”分离：

- 支持每天、工作日、每周、每月循环。
- 每周和每月仅设置一个执行日。
- 当天勾选只完成当天，循环任务本身继续有效。
- 只保存实际完成记录，不记录漏做日期。
- 检查项状态跨周期保留，不自动重置。
- 使用服务端配置时区判断“当天”。
- 已完成视图将每次循环完成记录作为独立条目展示。

## 数据和接口

- 为 `tasks` 增加循环配置：
  - `recurrence_type`：`daily | weekdays | weekly | monthly | null`
  - `recurrence_start_date`
  - `recurrence_end_date`，可为空
  - `recurrence_weekday`：每周执行星期
  - `recurrence_monthday`：每月执行日期
  - `reminder_offset_minutes`：相对截止时间的提前提醒分钟数
- 新建 `task_occurrences` 表保存实际完成记录：
  - 独立 UUID、原任务 ID、计划执行日期、完成时间。
  - 保存完成当时的标题、描述、日期、优先级、清单及标签快照，避免以后编辑循环任务篡改历史。
  - 对 `(task_id, occurrence_date)` 建唯一约束，保证当天重复点击幂等。
- `TaskCreate`、`TaskUpdate`、`TaskResponse` 和前端类型增加统一的 `recurrence` 对象；非循环任务返回 `null`。
- 完成接口保持 `POST /tasks/{id}/complete`：
  - 普通任务沿用现有状态切换。
  - 循环任务验证今天是否为执行日，创建当天 occurrence，主任务保持未完成。
  - 重复调用返回已有 occurrence，不重复写入。
- 取消完成接口允许删除对应 occurrence；取消今天的完成后，任务重新出现在今日视图。
- 已完成查询同时返回普通已完成任务和 occurrence；occurrence 携带 `source_task_id`、`occurrence_date`、`is_recurring_occurrence=true`，详情只读。
- 删除循环任务表示停止未来循环，已有完成历史继续保留；永久删除时级联删除历史。恢复后按原规则继续计算，不补建漏做记录。

## 周期计算与界面

- 循环设置放在任务详情的日期与提醒区域，提供“不循环、每天、工作日、每周、每月”。
- 设置循环必须选择开始日期；结束日期可选且不得早于开始日期。
- 每周默认取开始日期的星期，可选择另一个星期；每月默认取开始日期的日号。
- 每月 29、30、31 日遇到短月份时顺延到该月最后一天。
- 全天任务按本地日期执行；定时任务沿用开始时间，并在后续周期保持相同本地时刻。
- 提醒由原来的绝对 `reminder_at` 转换为相对提前量，在每个执行日计算实际提醒时间。
- 今日列表按规则动态计算应出现的任务：
  - 今天符合周期且尚无完成记录时显示。
  - 今天完成后从活动区移除，并进入已完成记录。
  - 过去未完成的周期不展示、不写入数据库。
- 列表行和详情增加循环图标及“每天 / 工作日 / 每周一 / 每月 31 日”等摘要。
- 编辑活动循环任务始终修改整个循环及后续执行；历史 occurrence 只读。
- 修改周期后不改动已有完成历史，从修改后的规则计算当天及未来周期。

## 测试与验收

- 数据库迁移支持升级和回滚，不影响已有普通任务。
- 覆盖每天、工作日、跨周、月末、闰年、开始/结束边界及时区跨日计算。
- 同一天多次完成循环任务只产生一条历史记录。
- 完成后今日任务消失，次日重新出现；昨天漏做不会产生历史。
- 检查项完成状态在次日保持，完成历史保存当时快照。
- 相对提醒在每天、跨月和夏令时场景下保持正确本地时间。
- 已完成视图可同时展示普通任务和多条循环完成记录，列表 key 与详情路由不冲突。
- 删除、恢复、永久删除循环任务符合历史保留策略。
- 桌面端与移动布局均可创建、编辑、完成和识别循环任务。
- 保持现有普通任务创建、完成、重开、筛选和分页行为不变。

## 约定

- 首版不支持自定义“每 N 天”、多个星期、多个每月日期或按完成时间滚动循环。
- 工作日固定为周一至周五，不处理法定节假日。
- 当前仍采用应用配置时区，不新增用户级时区设置。
- 不运行后台任务生成实例；执行日通过查询动态计算，只有完成时才持久化 occurrence。
